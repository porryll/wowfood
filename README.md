# WOWFOOD 简易下单系统

WOWFOOD 是一个给小摊、小店使用的轻量预订取餐系统。目标不是做成美团/外卖平台，而是让顾客能快速下单，商家能清楚看到订单、按顺序制作、现场收款。

## 一、产品定位

* **使用场景**：顾客提前点餐，到摊位自提。
* **支付方式**：现场付款，不接入线上支付。
* **用户身份**：手机号只用于联系和识别订单，不做复杂账号系统。
* **核心目标**：少步骤、少配置、手机上好用。

## 二、顾客端功能

### 1. 手机号

* 首次访问输入 11 位手机号。
* 手机号保存在本机 `localStorage`，下次打开自动带出。
* 页面展示脱敏手机号，例如 `138****8899`。
* 支持手动修改手机号。

> 说明：手机号不是强登录凭证，不用于保护敏感账户数据。系统只做简易订单识别。

### 2. 点餐

* 按分类展示菜单，例如：烧烤、炸货、小吃、卤肉、冰镇饮品。
* 商品展示名称、价格、规格、描述、标签、图片和售卖状态。
* 顾客可用 `+` / `-` 调整数量。
* 底部购物车实时显示件数和总金额。
* 支持展开购物车、修改数量、清空购物车。

### 3. 下单

* 选择预计取货时间，例如 `18:00`、`18:30`。
* 选择辣度：`不辣` / `微辣` / `中辣` / `重辣`。
* 可填写特殊备注。
* 提交后生成订单号，例如 `#05`。

### 4. 取餐凭证

提交成功后展示一张清晰的小票卡片：

* 订单号
* 预计取货时间
* 手机尾号
* 菜品明细
* 现场应付金额
* 当前状态

订单状态统一为：

* `待制作`
* `制作中`
* `待取货`
* `已完成`

未完成订单再次打开页面时，优先展示取餐凭证。

## 三、商家端功能

### 1. 后台入口

* 输入 4 位 PIN 码进入商家后台。
* PIN 只用于防止普通顾客误入后台，不做企业级权限系统。

### 2. 接单状态

* 姐姐端可以手动切换 `营业中` / `暂停接单`。
* `暂停接单` 时，顾客端仍可浏览菜单，但不能提交订单。
* `暂停接单` 时，顾客端展示姐姐端配置的提示文案。
* 第一版不做复杂营业时间规则，后续如有需要再增加自动营业时间。

### 3. 订单看板

* 按预计取货时间升序排列。
* 订单卡片展示订单号、取货时间、手机尾号、菜品明细、备注和应收金额。
* 商家可以一键切换订单状态：
  `待制作` -> `制作中` -> `待取货` -> `已完成`

### 4. 菜品管理

姐姐端可以直接维护当天售卖的分类和菜品，不需要改代码。

* **分类管理**：支持新增、编辑、删除和排序分类。
* **分类下商品**：每个分类下面可以配置多个商品。
* **商品管理**：商品支持新增、编辑、删除和调整所属分类。
* **商品字段**：包括名称、价格、规格、描述、标签、分类、图片。
* 支持切换 `在售` / `已售罄`。
* 售罄商品在顾客端不可加购。
* 分类和商品调整后，顾客端菜单自动按最新配置展示。

## 四、订单号规则

* 订单号按当天从 `#01` 开始递增。
* 每天自动重置。
* 同一时间下单时，系统需要保证订单号不重复。

## 五、商品数据字段

每个商品包含以下字段：

* **商品名称**：如“招牌牛肉串”
* **所属分类**：如“烧烤”
* **售卖价格**：如 `25`
* **规格单位**：如“10串” / “份” / “瓶”
* **卖点描述**：如“鲜肉现穿，碳烤入味”
* **商品图片**：图片 URL，未设置时展示默认图
* **商品标签**：如“招牌”、“热销”
* **售卖状态**：`在售` / `已售罄`

姐姐端编辑商品时，需要提供一个简单表单：

* 商品名称
* 所属分类
* 售卖价格
* 规格单位
* 卖点描述
* 商品图片
* 商品标签
* 售卖状态

## 六、暂不做的功能

为了保持简单，第一版不做：

* 线上支付
* 配送
* 优惠券和会员系统
* 复杂账号登录
* 多门店管理
* 评价系统
* 自动退款
* 精细库存扣减

## 七、移动端与 PWA 适配标准

WOWFOOD 第一版优先保证手机端体验。桌面端能正常使用即可，不作为主要设计目标。

### 1. 适配范围

* 默认按手机竖屏设计。
* 重点覆盖 `320px` 到 `430px` 宽度的移动设备。
* 需要兼容 iPhone Safari、Android Chrome，以及添加到手机桌面后的 PWA 模式。
* 横屏模式不需要单独设计，但页面不能错乱或关键按钮不可见。

### 2. 布局规则

* 页面不能写死为固定宽度，例如不能依赖 `375px` 设计稿宽度。
* 页面主体在手机上占满宽度，在大屏上可以设置最大宽度并居中。
* 底部购物车、提交订单按钮、商家操作栏必须固定在安全可点击区域。
* 商品名、规格、备注、金额等内容过长时，需要换行或截断，不能撑破布局。
* 弹窗、抽屉、购物车明细在小屏手机上不能超过可视区域。

### 3. 触控规则

* 主要按钮高度不低于 `44px`。
* `+` / `-`、状态切换、返回、关闭等高频按钮要适合拇指点击。
* 不依赖鼠标 hover 展示关键功能。
* 输入手机号、备注、PIN 码时，键盘弹出后不能遮挡提交按钮。

### 4. 安全区域

页面需要正确处理刘海屏、圆角屏和底部 Home 指示条。

HTML 需要设置：

```html
<meta
  name="viewport"
  content="width=device-width, initial-scale=1.0, viewport-fit=cover"
/>
```

底部固定栏需要预留安全区：

```css
.bottom-bar {
  padding-bottom: calc(12px + env(safe-area-inset-bottom));
}
```

### 5. PWA 要求

* 提供 Web App Manifest。
* `display` 使用 `standalone`。
* 提供 `192x192` 和 `512x512` 应用图标。
* 设置 `theme_color`，让系统状态栏颜色和页面风格一致。
* 支持添加到手机桌面。

### 6. 离线与弱网规则

* 菜单和商品图片可以缓存。
* 下单必须连接服务器成功后才算提交成功。
* 网络不可用时，提交订单按钮需要明确提示失败原因。
* 不能在离线状态下展示“下单成功”。

### 7. 验收设备与场景

上线前至少检查：

* `320px` 小屏手机宽度
* `375px` 常见 iPhone 宽度
* `390px` / `414px` 主流手机宽度
* iPhone Safari 普通网页
* iPhone 添加到主屏幕后打开
* Android Chrome 普通网页
* Android Chrome 安装后打开
* 手机横屏
* 手机号输入时键盘弹出
* 购物车展开和收起
* 提交订单成功和失败
* 商家端订单状态切换

## 八、参考项目取舍

可以参考 `guchengwuyue/yshop-drink` 的 H5/小程序移动端视觉，但 WOWFOOD 不直接采用它的完整工程架构。

### 1. 可以借鉴的部分

* **点餐页结构**：顶部店铺信息、左侧分类、右侧商品列表。
* **商品卡片**：商品图、名称、描述、价格、售罄状态、`+` / `-` 操作。
* **底部购物车**：黑色金额区 + 主色结算按钮 + 数量角标。
* **购物车抽屉**：展开查看已选商品、修改数量、清空购物车。
* **下单页层级**：白色信息区块、商品明细、取货时间、备注、合计金额。
* **订单详情页**：大号取餐号、订单状态进度、商品明细和取餐信息。
* **整体风格**：浅灰背景、白色内容区、清晰留白、鲜明主色、适合手机触控的大按钮。

### 2. 不采用的部分

* Java / Spring Boot 后端架构。
* UniApp 多端工程作为项目基础。
* 外卖配送、地址管理、配送距离。
* 微信支付、支付宝、余额支付。
* 优惠券、积分、会员、充值。
* 多门店、SaaS 多租户。
* 桌台扫码、多人协同点餐。
* 云小票打印、收银台硬件。
* 复杂登录、OAuth2、企业级权限系统。

### 3. WOWFOOD 的简化方向

参考项目的体验可以压缩成 WOWFOOD 第一版的 4 个核心页面：

* **点餐页**：分类、商品、购物车。
* **确认下单页**：手机号、取货时间、辣度、备注、应付金额。
* **取餐凭证页**：订单号、状态、手机尾号、菜品明细、现场付款金额。
* **商家订单页**：按取货时间排序，切换订单状态。

如果后续直接复用参考项目中的代码、图片或样式片段，需要保留它的 MIT License 版权和许可说明。

## 九、推荐技术栈

WOWFOOD 第一版使用轻量 Web 技术栈，优先保证开发速度、手机端体验和后续维护成本。

### 1. 前端

* **Vite + React + TypeScript**：用于开发 PWA 前端。
* **Tailwind CSS**：用于快速实现移动端界面和统一样式。
* **React Router**：用于区分顾客端页面和商家端页面。
* **Zustand**：用于管理购物车、手机号、当前订单等轻量状态。
* **vite-plugin-pwa**：用于生成 PWA 所需的 Service Worker 和 Manifest。

### 2. 后端与数据

第一版推荐使用 Supabase：

* **Postgres**：存储商品、分类、订单和商家配置。
* **Supabase Realtime**：让商家端订单看板和顾客端订单状态自动刷新。
* **Supabase Storage**：后续如需上传商品图片时使用；第一版也可以先直接使用图片 URL。

### 3. 部署

* 前端部署到 **Cloudflare Pages**。
* 数据和实时能力使用 **Supabase**。
* 如果主要面向国内用户且访问速度不理想，再评估腾讯云 CloudBase。

### 4. 第一版页面路由

* `/`：顾客点餐页。
* `/orders`：顾客订单页。
* `/checkout`：确认下单页。
* `/ticket/:orderId`：取餐凭证页。
* `/admin`：商家订单看板。
* `/admin/menu`：商家菜品管理。

本地体验端口：

* **C 端**：`http://localhost:1888/`
* **姐姐端**：`http://localhost:1666/`
* **本地数据服务**：`http://127.0.0.1:1777/`，只供开发环境同步分类、商品和订单。

本地开发时需要同时启动：

```bash
npm run dev:data
npm run dev:customer
npm run dev:admin
```

### 5. 不选重型架构

第一版不使用：

* Java / Spring Boot
* 微服务
* 自建服务器
* 复杂后台权限系统
* 多端 UniApp 工程

## 十、第一版实现顺序

第一版先做能支撑真实下单的数据和管理能力，再做顾客端体验，避免 C 端页面依赖写死数据。

### 1. 数据模型

先定义基础数据：

* 分类
* 商品
* 订单
* 订单明细
* 商家配置

### 2. 姐姐端菜品管理

先实现 `/admin/menu`：

* 新增、编辑、删除、排序分类。
* 在分类下新增、编辑、删除商品。
* 配置商品名称、价格、规格、描述、标签、图片。
* 切换商品 `在售` / `已售罄`。

### 3. 顾客端点餐

再实现 `/`：

* 从真实分类和商品数据渲染菜单。
* 支持加入购物车、修改数量、清空购物车。
* 售罄商品不可加购。
* 底部固定两个主入口：`点餐` 和 `订单`。

### 4. 确认下单

实现 `/checkout`：

* 填写或确认手机号。
* 选择取货时间。
* 选择辣度。
* 填写备注。
* 提交订单并生成当天排号。

### 5. 姐姐端订单看板

实现 `/admin`：

* 按预计取货时间展示订单。
* 查看手机号尾号、菜品明细、备注、应收金额。
* 一键切换订单状态。

### 6. 取餐凭证

最后完善 `/ticket/:orderId`：

* 展示大号订单号。
* 展示订单状态。
* 展示取货时间、手机尾号、菜品明细和现场付款金额。
* 未完成订单再次打开顾客端时优先展示。

### 7. 顾客端订单页

实现 `/orders`：

* 展示当前手机号对应的订单。
* 未完成订单优先展示。
* 点击订单进入取餐凭证页。
* 底部固定 `点餐` / `订单` 两个 tab。
